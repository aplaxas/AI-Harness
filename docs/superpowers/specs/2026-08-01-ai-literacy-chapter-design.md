# AI Literacy 챕터 설계

## 목적

주니어 개발자가 규칙 기반 프로그램과 머신러닝의 차이를 이해하고, LLM을 결정론적 컴파일러처럼 다루면 왜 실패하는지 설명할 수 있게 한다.

## 대상 문서와 범위

- 대상: `draft/harness01-rev.md`
- 기존 `2. AI는 무엇인가 — 결정론을 버린 첫 번째 추상화`를 새 AI Literacy 챕터로 교체한다.
- 이후 장의 핵심 주장과 중복되는 설명은 새 챕터에서 제거하거나 연결 문장으로 축약한다.
- 기존 3장 이후의 번호와 전체 논지는 유지한다.

## 내러티브

새 2장은 다음 순서로 진행한다.

1. 에어컨 다이얼 사례로 사람이 명시한 규칙을 설명한다.
2. 키와 몸무게 사례로 데이터에서 관계를 학습하는 머신러닝을 설명한다.
3. 오디오 믹서의 노브를 비유로 모델 파라미터를 설명한다.
4. 번역과 Houston 분류 사례로 모델의 출력이 의미 이해 자체가 아니라 학습된 패턴과 맥락에 따른 확률적 예측임을 설명한다.
5. 기존 추상화 사다리, 할루시네이션, 과잉 구현과 누락을 결과의 실무적 특성으로 연결한다.
6. “흔들리는 출력을 다루려면 실행·관찰·검증 루프가 필요하다”는 문장으로 Agent 장에 연결한다.

## 핵심 메시지

- 규칙 기반 프로그램에서는 개발자가 규칙과 임계값을 직접 작성한다.
- 머신러닝에서는 데이터로부터 조정된 파라미터가 입력과 출력의 관계를 구성한다.
- 파라미터는 데이터 자체나 사람이 읽는 지식 목록이 아니라, 학습 과정에서 조정된 수치다.
- 모델 출력은 학습 데이터와 현재 맥락을 조건으로 한 예측이다.
- LLM 생성은 설정에 따라 재현성을 높일 수 있지만, 컴파일러와 같은 결정론적 계약으로 간주해서는 안 된다.
- 따라서 품질은 프롬프트만이 아니라 경계, 도구, 검증, 상태, 관측을 포함한 harness로 관리해야 한다.

## 이미지

GPT Image 2.0으로 다음 세 이미지를 생성해 `draft/images/`에 저장한다.

1. `ai-rule-vs-learning.png`
   - 규칙 기반 제어와 데이터 기반 학습의 대비
   - 에어컨 다이얼과 키·몸무게의 관계를 한 화면에서 비교
2. `ai-parameters-mixer.png`
   - 오디오 믹서의 많은 노브가 함께 출력을 조정하는 비유
   - 특정 노브 하나가 단일 개념과 일대일 대응한다는 오해는 피한다.
3. `ai-context-probability.png`
   - 같은 단어 또는 문장이 주변 맥락과 학습 분포에 따라 다른 출력 확률을 갖는 모습
   - 번역과 지역 분류의 직관을 하나의 장면으로 통합한다.

공통 스타일은 밝은 미색 배경, 검은 선, 제한된 녹색·노란색·빨간색 포인트를 사용한 현대적인 교육용 편집 일러스트다. 긴 한글과 장식용 문구는 이미지에 넣지 않는다. 필요한 의미와 정확한 용어는 본문 및 캡션에서 전달한다. 이미지 비율은 글 본문에 적합한 가로형으로 통일한다.

## 문체와 편집 원칙

- 기존 원고의 짧고 단정적인 문장과 개발자 관점의 비유를 유지한다.
- PPT의 낡은 이미지나 문장을 복제하지 않고 교육 아이디어만 재해석한다.
- 전문 용어는 처음 등장할 때 쉬운 말로 설명한다.
- 머신러닝과 LLM을 과도하게 의인화하지 않는다.
- “AI는 항상 비결정적이다”처럼 기술적으로 과도한 단정은 피하고 실무적 차이를 설명한다.
- 이미지는 각 개념이 처음 등장한 직후에 배치하고 한 줄 캡션을 붙인다.
