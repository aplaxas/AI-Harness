# AI Harness 5시간 강의 덱 디자인

## 목적

`harness/`의 1~3편을 주니어 개발자 대상 5시간 발표용 PowerPoint로 재구성한다. 원고를 축약한 읽기 자료가 아니라, 강사가 말로 설명하는 동안 화면이 논지와 흐름을 잡아 주는 강의 덱을 만든다.

완성물은 편집 가능한 `.pptx` 한 개다. 강사는 선택 모듈을 덜어내 3시간 또는 2시간 강의로 줄일 수 있어야 한다.

## 대상과 사용 방식

- 대상: AI 코딩을 사용해 봤지만 결과가 흔들리는 이유와 검증 방법을 체계적으로 배우지 못한 주니어 개발자
- 전체 시간: 휴식 제외 5시간
- 발표 방식: 화면에는 핵심 메시지를 짧게 제시하고, 상세 설명은 강사가 발표자 노트를 참고해 말한다.
- 화자: 원고의 저자 1인칭을 유지한다. 저자가 경험하지 않은 일을 경험한 것처럼 추가하지 않는다.

## 핵심 메시지

덱 전체는 다음 뼈대를 흔들지 않는다.

1. harness는 AI가 일하는 환경이며 권한·도구·검증·상태·관측의 다섯 축으로 본다.
2. 핵심은 검증이며, 검증 결과가 AI에게 자동으로 되먹임되어야 `생성 → 검증 → 수정 → 재검증` 루프가 된다.
3. 판단과 책임은 사람에게 남는다.
4. 구현 전 정본은 spec과 plan이고, 구현 후 현재 동작의 정본은 실제 소스코드다.
5. 작업에 맞지 않는 단계는 건너뛸 수 있다. 모든 작업에서 모든 단계를 수행하는 것은 목적이 아니다.

## 전체 구성

전체는 약 70장으로 설계한다. 핵심 본편은 약 55장, 선택 모듈은 약 15장이다. 실제 제작 과정에서 메시지 밀도와 가독성을 위해 장수는 소폭 달라질 수 있다.

네 막의 본문은 총 280분이며, 남은 20분은 강의 안내·막 사이 전환·마지막 질의응답에 사용해 전체 300분을 맞춘다.

### 1막. 왜 Harness인가 — 약 55분

- 카파시의 vibe coding 원문
- 토발즈 커밋 메시지 원문
- 두 원문을 읽는 저자의 해석
- 핵심 질문: AI를 쓰느냐가 아니라 어디까지 맡길 것인가
- 규칙 기반 시스템과 학습의 차이
- 파라미터와 확률적 출력
- 컴파일러와 다른 자연어의 계약
- LLM과 Agent의 차이
- 판단 지점을 사람이 설계해야 하는 이유

AI 기초 설명 일부는 선택 모듈로 분리해 축약 시 덜어낼 수 있게 한다.

### 2막. Harness의 구조 — 약 50분

- Harness Engineering의 정의
- 권한·도구·검증·상태·관측의 다섯 축
- 토발즈 사례를 다섯 축에 다시 매핑
- 검증 결과가 자동으로 돌아와야 하는 이유
- 생성·검증·수정·재검증 루프
- Agent·Task·Skill 관심사의 분리
- 강제 수준이 서로 다른 코딩 원칙
- 판단과 책임은 사람의 몫이라는 결론

### 3막. 무엇을 강제할 것인가 — 약 70분

- SDD: 틀린 것을 빠르게 만들지 않는다
- DDD: 같은 단어를 같은 뜻으로 쓴다
- TDD: 원하는 행동을 코드보다 먼저 정한다
- Deep Module: 호출자가 알아야 할 것을 줄인다
- 각 방법론의 `왜 필요한가 → 주니어가 흔히 하는 오해 → harness에서 강제하는 법`
- 네 방법론을 산출물과 harness 축으로 비교

각 방법론의 보충 사례는 선택 모듈로 둔다.

### 4막. 어떤 흐름으로 돌릴 것인가 — 약 105분

- AI가 남기는 인지 부채
- 여섯 단계의 전체 지도
- 정본이 이동하는 시점
- 요구사항 합의
- 구현 순서 설계
- 구현 전 검토
- 구현·검증
- 흐름 복원
- 지식화
- 작업 크기에 따라 단계를 생략하는 기준
- SDD·DDD·TDD가 흐름 안에서 작동하는 위치
- Deep Module이 단계가 아니라 리뷰 질문으로 남는 이유

`주문 취소`를 여섯 단계 전체를 잇는 연속 사례로 사용한다.

## 도입 원문 슬라이드

카파시와 토발즈의 원문은 각각 한 슬라이드 전체를 사용한다.

### 카파시

- `harness/images/AndrejCarpathy.png`의 원문 캡처를 크게 배치한다.
- 슬라이드 안에 해석이나 요약을 섞지 않는다.
- 이미지가 16:9 화면에서 잘리지 않도록 비율을 유지하고 주변 여백을 허용한다.
- 출처 링크는 발표자 노트의 `[Sources]` 블록에 기록한다.

### 토발즈

- 1편에 인용된 커밋 메시지 전문을 한 슬라이드에 표시한다.
- 코드·터미널 문법을 연상시키는 고정폭 글꼴과 어두운 코드 영역을 사용하되 본문을 읽을 수 있는 크기를 유지한다.
- 해석은 다음 슬라이드부터 시작한다.
- 커밋 링크는 발표자 노트의 `[Sources]` 블록에 기록한다.

## 시각 디자인

선택한 방향은 **개발자 친화 하이브리드**다.

- 16:9 화면
- 밝은 회백색 바탕과 먹색 본문
- 파란색 계열 한 가지를 주 포인트 색으로 사용
- 한국어 본문은 Pretendard 계열, 코드·파일·명령은 고정폭 글꼴 사용
- 제목은 36pt 이상, 본문은 주로 20~26pt로 설계
- 한 슬라이드에 핵심 메시지 하나
- 일반 슬라이드는 장식보다 타이포그래피와 여백으로 계층을 만든다.
- 코드, 파일명, 명령, 생성·검증 흐름에서만 터미널·코드 문법을 제한적으로 사용한다.
- 카드형 UI, 배지, 장식 아이콘, 과한 그림자와 그라데이션은 사용하지 않는다.
- 단순 흐름은 PowerPoint 기본 선과 화살표로 표현하고, 복잡한 다이어그램은 만들지 않는다.
- 하단에 편·절 표시와 페이지 번호를 일관되게 둔다.

## 슬라이드 유형

반복되는 레이아웃은 다음 유형으로 제한한다.

1. 표지: 제목과 부제만 둔다.
2. 막 구분: 원고의 핵심 문장 하나와 절 번호를 크게 보여준다.
3. 핵심 주장: 큰 문장과 짧은 근거 1~3개를 둔다.
4. 비교: 두 개념의 차이를 좌우 또는 간단한 표로 보여준다.
5. 흐름: 단계와 되먹임 관계를 한 방향의 선으로 보여준다.
6. 원문: 카파시 캡처 또는 토발즈 커밋 메시지를 한 장 전체에 보여준다.
7. 사례: 주문 취소 사례의 현재 단계와 산출물을 보여준다.
8. 정리: 해당 막에서 기억할 문장 2~4개를 보여준다.

인접 슬라이드는 같은 실루엣이 반복되지 않게 배치한다.

## 발표자 노트

각 슬라이드에는 다음을 필요한 만큼 기록한다.

- 원고에 근거한 설명
- 이전·다음 슬라이드를 잇는 전환 문장
- 예상 소요 시간
- 선택 모듈인지와 생략할 때 이어갈 슬라이드
- 외부 주장이나 이미지의 `[Sources]` 블록

노트는 원고의 내용을 바꾸지 않는다. `✍️ [채우기]`는 지어내지 않고, 필요한 경우 `저자 경험 추가 자리`라고만 표시한다.

## 시간 축약 설계

마지막 발표자용 부록에 시간별 생략 가이드를 둔다.

- 5시간: 본편과 선택 모듈 전체
- 3시간: AI 기초 보충, 방법론별 보충 사례, 여섯 단계의 일부 상세 예시를 생략
- 2시간: 도입 원문, 다섯 축, 검증 루프, 네 방법론 요약, 여섯 단계 지도와 정본 이동만 유지

생략 단위는 개별 슬라이드가 아니라 연속된 모듈로 표시해 강의 흐름이 끊기지 않게 한다.

## 콘텐츠 원칙

- 원고의 문장을 그대로 옮기기보다 발표 화면에 맞게 줄인다.
- 사실과 저자의 해석을 같은 슬라이드에서 혼동하지 않게 구분한다.
- 새로운 방법론·도구·프레임워크를 추가하지 않는다.
- 긴 코드 예시는 만들지 않는다.
- 원고에 없는 실제 경험을 추가하지 않는다.
- 기존 이미지 세 장과 카파시 이미지는 의미가 맞는 곳에서 각각 한 번만 사용한다.
- 외부 자료를 새로 조사해 논지를 확장하지 않는다. 원고가 이미 인용한 자료의 출처만 발표자 노트에 남긴다.

## 산출물과 검증

최종 산출물은 저장소 루트의 `AI-Harness-5h-Lecture.pptx`다.

전달 전 다음을 확인한다.

1. 모든 슬라이드를 PNG로 렌더링한다.
2. 각 슬라이드를 전체 크기로 확인해 잘림, 겹침, 의도하지 않은 줄바꿈을 수정한다.
3. 전체 몽타주로 흐름, 밀도, 시각적 반복을 확인한다.
4. 슬라이드 캔버스 밖으로 넘친 개체가 없는지 검사한다.
5. 발표자 노트, 예상 시간, 선택 모듈 표시, `[Sources]` 블록을 확인한다.
6. 5시간·3시간·2시간 축약 경로가 연속된 이야기로 이어지는지 확인한다.
7. 원고의 핵심 뼈대와 용어가 바뀌지 않았는지 대조한다.

## 범위 밖

- 4편에서 예고한 Agent·Skill 파일 작성 실습을 새로 창작하는 일

- 애니메이션, 영상, 음향 효과
- 원고에 없는 라이브 코딩 예제나 새로운 도구 소개
- 원고 파일 자체의 편집
