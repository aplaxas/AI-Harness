# AI Harness 5시간 강의 실라버스 디자인

## 목적

`AI-Harness-5h-Lecture-final.pptx`로 진행하는 강의에 앞서 참석자에게 보낼 3쪽짜리 안내 문서를 만든다. 발표자료의 내용을 압축해서 반복하기보다, 참석자가 강의의 목적과 진행 순서, 준비 사항을 짧은 시간 안에 파악하도록 한다.

## 독자와 톤

- 독자: AI를 개발 업무에 적용하려는 주니어 개발자와 실무 개발자
- 문체: 짧고 단정한 `~다`체
- 관점: 교과서식 정의보다 “이 강의에서 무엇을 보고 가져갈 것인가”에 집중한다
- 시각 스타일: 기존 PPT와 이어지는 흰 배경, 짙은 남색 본문, 파란색 강조의 담백한 개발자 친화 스타일

## 결과물

- 배포용 PDF 1개
- 수정 가능한 DOCX 1개
- A4 세로 3쪽
- 별도 표지 없이 첫 쪽 상단에 제목과 핵심 메시지를 배치한다

## 페이지 구성

### 1쪽 - 강의 소개

- 제목과 한 문장 소개
- 이 강의가 답하는 핵심 질문
- 추천 대상
- 학습 목표 4개
- 5시간 운영 방식 요약

### 2쪽 - 5시간 커리큘럼

- 1부: AI와 Agent를 보는 관점
- 2부: AI Harness의 정의와 다섯 축
- 3부: 개발 방법론이 Harness가 되는 방식
- 4부: 실제 개발 흐름과 여섯 단계
- 마무리: 검증 가능한 만큼만 위임한다
- 각 구간의 예상 시간과 핵심 산출물을 함께 표시한다

### 3쪽 - 참여 안내

- 사전 준비와 권장 배경지식
- 강의 진행 방식
- 강의 후 가져갈 수 있는 것
- 시간이 줄어들 때 선택 모듈을 덜어내는 운영 원칙
- 일정, 장소, 강사명처럼 주최 측에서 채울 항목은 눈에 띄는 빈칸으로 남긴다

## 콘텐츠 원칙

- Harness를 AI가 일하는 환경으로 정의하고 권한, 도구, 검증, 상태, 관측의 다섯 축을 유지한다.
- 생성, 검증, 수정, 재검증의 루프와 자동 되먹임을 중심에 둔다.
- 판단과 책임은 사람의 몫이라는 결론을 유지한다.
- 구현 전 정본은 spec과 plan이고, 구현 후 현재 동작의 정본은 실제 소스코드라는 구분을 반영한다.
- 모든 작업에 여섯 단계를 강제하지 않으며 위험에 맞게 단계를 생략할 수 있음을 밝힌다.

## 검증 기준

- 정확히 3쪽으로 렌더링된다.
- 모든 텍스트가 잘림이나 겹침 없이 읽힌다.
- 강의 자료의 핵심 용어와 순서가 일치한다.
- 참석자가 직접 채워야 할 내용은 없고, 주최자용 빈칸만 남는다.
- PDF와 DOCX의 페이지 구성이 동일하다.
