# 스킬은 어디에 설치되고, Python은 어디에서 실행되는가

> 2026-11-06 학습 메모. 강의 본편의 순서와 별개로 정리한 기록이다.
> 관련 자료: [집필 목차](AI-For-Work-Index.md). 이전·다음 편은 지정하지 않았다.

## 내가 확인한 사례

나는 Schedule Basis 문서를 만드는 두 스킬을 로컬에서 테스트했다. `schedule-basis-md`는 입력 Excel에서 Markdown 문서와 검토 보고서를 만들고, `schedule-basis-pdf`는 최종 Markdown을 PDF로 바꾼다. 두 스킬은 Python 스크립트를 포함한다.

나는 두 스킬을 Schedule Basis 플러그인으로 묶어 클라우드에 업로드했고, ChatGPT 웹에서 정상 동작하는 것을 확인했다. 그러나 데스크톱의 로컬 작업에서는 같은 플러그인의 스크립트가 내 PC의 Python으로 실행됐다.

여기서 내 질문은 두 가지였다. 다른 노트북에 Python이 없어도 이 스킬을 쓸 수 있는가. 웹에서 쓸 수 있다면 내 PC의 캐시를 지워도 되는가.

## 배포 위치와 실행 위치는 별개다

나는 스킬을 **작업 지침과 필요한 자료를 묶은 폴더**로 이해한다. `SKILL.md`에는 수행 방법을 적고, 필요하면 스크립트·템플릿·참고 자료를 함께 넣는다. 플러그인은 이런 스킬들을 묶어 설치하고 배포하는 단위다. [OpenAI 스킬 문서](https://learn.chatgpt.com/docs/build-skills)

클라우드에 스킬을 업로드했다는 사실은 배포본을 클라우드에서 관리한다는 뜻이다. 그 안의 Python 스크립트가 반드시 클라우드에서 실행된다는 뜻은 아니다.

나는 다음 세 가지를 따로 확인해야 한다.

| 구분 | 확인할 질문 | Schedule Basis 사례 |
| --- | --- | --- |
| 배포 | 스킬 패키지를 어디에서 받는가 | 클라우드에 업로드한 플러그인 |
| 설치 | 지금 사용하는 스킬 사본은 어디에 있는가 | 로컬 플러그인 캐시 또는 클라우드 작업 환경 |
| 실행 | Python 명령은 어느 컴퓨터에서 실행되는가 | 작업 모드에 따라 클라우드 또는 내 PC |

Python 파일을 묶어서 배포하는 것과 Python 실행 프로그램·라이브러리를 준비하는 것도 별개다. 필요한 도구는 실제 실행 환경에 있어야 한다.

## Python 실행 위치를 네 가지 사용 방식으로 비교한다

아래 표는 각 행에 적은 실행 조건을 기준으로 한다. 앱 이름만으로 실행 위치를 결정하는 표는 아니다.

| 사용 방식 | Python 실행 위치 | 내 PC에 Python 설치 필요 |
| --- | --- | --- |
| ChatGPT 웹 · Chat의 클라우드 코드 실행 | 클라우드 코드 실행 환경 | 없음 |
| ChatGPT 웹 · Work의 클라우드 실행 | Work Cloud 실행 환경 | 없음 |
| 데스크톱 · Work의 로컬 실행 | 작업에 연결된 PC | 있음 |
| 데스크톱 · Codex의 로컬 실행 | 작업에 연결된 PC | 있음 |

데스크톱에서도 클라우드 작업을 열 수 있다. 지원되는 로컬 연결을 사용하면 웹에서도 연결된 PC의 파일과 도구를 이용할 수 있다. 따라서 나는 **어느 화면에서 여는가보다 어떤 실행 환경을 사용하는가**를 확인한다. [Work 안내](https://learn.chatgpt.com/docs/get-started-with-work), [원격 연결 안내](https://learn.chatgpt.com/docs/remote-connections)

일상적인 이해로는 “웹의 클라우드 작업은 서버 환경을 쓰고, 데스크톱의 로컬 작업은 내 PC 환경을 쓴다”고 정리할 수 있다. 다만 이 문장에서 ‘클라우드 작업’과 ‘로컬 작업’이라는 조건을 빼면 부정확해진다.

## Python이 없는 다른 노트북에서는 어떻게 되는가

내가 다른 노트북에서 클라우드 작업으로 이 스킬을 사용한다면, 그 노트북에 Python을 설치할 필요는 없다. 입력 Excel을 작업에 첨부하고 클라우드에서 결과물을 받으면 된다. 필요한 Python과 라이브러리는 클라우드 실행 환경에 있어야 한다.

반대로 그 노트북에서 로컬 작업으로 실행한다면 Python과 관련 도구가 필요하다. 현재 설치 사본의 지침에 적힌 요구 사항은 다음과 같다.

| 스킬 | 필요한 실행 도구 |
| --- | --- |
| `schedule-basis-md` | Python 3.11 이상, `openpyxl` |
| `schedule-basis-pdf` | Python 3.11 이상, `markdown-it-py`, `pypdf`, Chrome 또는 Edge |

PDF 스킬에는 Python 외에 브라우저도 필요하다. 웹 Chat에서 성공했다는 사실만으로 다른 실행 환경의 PDF 생성까지 보장되지는 않는다. 나는 새 환경에서 Markdown 생성과 PDF 생성을 각각 확인한다.

## 로컬 원본·캐시·클라우드 배포본·결과물은 다르다

이번에 확인한 내 PC의 구조는 다음과 같다.

| 구분 | 위치 또는 내용 | 역할 |
| --- | --- | --- |
| 개발 원본 | `C:\Develop\Study\codex-work-sample\schedule-sample\skills\` | 수정하고 재배포할 소스 |
| 클라우드 배포본 | 업로드한 Schedule Basis 플러그인 | 웹 등에서 사용하는 배포 패키지 |
| 로컬 캐시 | 아래 경로 | 데스크톱에서 읽고 실행하는 설치 사본 |
| 결과물 | 입력 작업 폴더의 Markdown·검토 보고서·PDF | 스킬로 생성한 업무 문서 |

```text
C:\Users\JongminLee\.codex\plugins\cache\
└─ created-by-me-remote\
   └─ schedule-basis\
      ├─ .codex-remote-plugin-install.json
      └─ 0.1.0\
         ├─ plugin.json
         └─ skills\
            ├─ schedule-basis-md\
            └─ schedule-basis-pdf\
```

캐시는 단순한 임시 쓰레기 파일만을 뜻하지 않는다. 공식 문서는 플러그인을 버전별 캐시 경로에 설치하고, 설치 사본에서 불러오는 구조를 설명한다. [플러그인 패키지 문서](https://developers.openai.com/plugins/build/plugins)

이 폴더에는 원격 플러그인 ID를 기록한 파일도 있었다. 여기서부터는 내 해석이다. 발견한 폴더는 업로드 전의 테스트 찌꺼기라기보다, 클라우드 플러그인을 로컬에서 사용하기 위한 설치 사본으로 보는 것이 타당하다.

내 목적은 클라우드 배포본과 개발 원본을 유지하고 Schedule Basis의 로컬 캐시만 정리하는 것이다. 이때 나는 다음을 구분한다.

- 해당 캐시 폴더의 파일 삭제는 클라우드 배포본 자체를 삭제하는 작업이 아니다.
- 플러그인 관리 화면의 제거는 설치 상태까지 바꾸는 작업이므로 단순한 파일 정리와 구분한다.
- 캐시를 지워도 로컬 실행 작업이 클라우드 실행으로 전환되지는 않는다.
- 앱이 캐시를 다시 내려받는지, 언제 복구하는지는 이번에 확인하지 않았다.
- 전체 `plugins\cache`에는 다른 플러그인도 있으므로 Schedule Basis 정리 범위와 구분한다.

이번 학습에서는 파일이나 플러그인을 삭제하지 않았다.

## Claude Desktop과 비교하며 바로잡은 점

나는 처음에 “Claude Code CLI를 제외한 Claude Desktop의 실행은 모두 클라우드인가”라고 질문했다.

확인한 공식 문서는 현재 Cowork 세션을 클라우드에서 실행하고, PC의 파일이나 브라우저가 필요하면 Desktop 앱을 통해 접근한다고 설명한다. 다만 Team·Enterprise에는 PC의 격리된 가상 머신에서 실행하는 로컬 Cowork도 명시되어 있다. 따라서 ‘CLI 이외에는 전부 클라우드’라고 단정할 수 없다. [Cowork 안내](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork), [Team·Enterprise 실행 위치](https://support.claude.com/en/articles/13455879-use-claude-cowork-on-team-and-enterprise-plans)

여기서 나는 **클라우드 실행·로컬 가상 머신 실행·로컬 직접 실행**을 구분하게 됐다. 가상 머신은 PC 안에 마련한 별도의 격리된 컴퓨터 환경이다. 샌드박스는 접근 범위를 제한한 실행 환경을 뜻하며, 그 말만으로 클라우드인지 로컬인지 알 수는 없다.

| 방식 | Python이 있어야 하는 곳 | 호스트 PC에 직접 설치해야 하는가 |
| --- | --- | --- |
| 클라우드 실행 | 클라우드 실행 환경 내부 | 아니오 |
| 로컬 가상 머신 실행 | 내 PC 안의 가상 머신 내부 | 호스트에는 없어도 된다. 가상 머신 내부에는 필요하다 |
| 로컬 직접 실행 | 내 PC의 운영체제 환경 | 별도 실행 환경이 없다면 필요하다 |

나는 이번 대화에서 Claude의 실제 Python 경로나 가상 머신 환경을 직접 검사하지 않았다. Claude 관련 내용은 공식 문서에서 확인한 설명이며, 내가 직접 검증한 실행 사례와 구분한다.

## 다음에 내가 확인할 것

스킬을 다른 컴퓨터에서 사용할 때 나는 먼저 실행 모드, Python 버전, 실행한 스크립트 경로와 종료 코드를 확인한다. 파일이 생성됐다는 사실에 더해, 번들 스크립트가 실제로 실행됐는지도 확인한다.

Python 실행 위치가 확인되어도 작업 관리 시스템 전체가 같은 컴퓨터에서 동작한다고 단정하지 않는다. 내 업무에서 필요한 질문은 더 구체적이다. **이 스크립트는 어디서 실행되고, 필요한 도구와 입력 파일은 그곳에 준비되어 있는가.**

제품 기능과 기본 설정은 달라질 수 있다. 이 메모의 제품 설명은 2026-11-06에 확인한 문서와 오늘의 관찰을 기준으로 한다.
