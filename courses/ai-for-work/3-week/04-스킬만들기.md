# 4. skill-creator로 스킬 만들기 — 따라 하기

> [목차](index.md) · 이전: [3. 대화를 위키로 정리하는 스킬](03-대화정리.md) · 다음: [마무리 — 다음 칸과 발표](index.md#마무리--다음-칸과-발표)
>
> [1](01-스킬.md)에서 스킬 초안을 글로 썼다면, 여기서는 그 초안을 실제 스킬로 만든다. 화면 이름과 메뉴는 2026년 11월 2일에 두 회사의 공식 문서로 확인한 것이다. 앱은 자주 바뀌므로 강의 전에 다시 확인한다.

## 이 시간의 목표

유료 요금제의 Claude 데스크톱 앱과 ChatGPT 데스크톱 앱(Work·Codex)에서 skill-creator와 대화해 스킬 하나를 만들고, 시험하고, 켤 수 있다.

## 핵심 한 줄

**skill-creator는 스킬을 대신 써 주는 스킬이다. 그래도 무엇을 넣을지와 합격 여부는 내가 정한다.**

## 용어

- **skill-creator**: 스킬을 만드는 일을 돕는 스킬이다. 두 회사 모두 앱에 기본으로 넣어 두었다. 내가 원하는 일을 말하면 질문하고, 스킬 파일을 쓰고, 시험까지 돕는다.
- **SKILL.md**: 스킬의 본체인 글 파일이다. 맨 위에 이름(`name`)과 설명(`description`)이 있고, 그 아래에 순서와 규칙이 있다. 1에서 쓴 여섯 칸이 이 파일에 들어간다.
- **설명(description)**: AI가 "지금 이 스킬을 꺼낼까"를 정할 때 읽는 한두 문장이다. 여섯 칸 중 **언제 쓰나**가 여기에 들어간다. 이 문장이 흐리면 스킬이 있어도 꺼내지 않는다.
- **스킬 파일**: SKILL.md와 딸린 자료를 폴더째 묶은 것이다. Claude에서는 ZIP 파일이나 `.skill` 파일로, ChatGPT의 Codex에서는 내 컴퓨터의 폴더로 저장된다.

## 시작 전에

### 이 글의 기준 환경

| | Claude | ChatGPT |
| --- | --- | --- |
| 앱 | Claude 데스크톱 앱 (Windows·Mac) | ChatGPT 데스크톱 앱. 그 안에서 Work를 켜거나 Codex를 고른다 |
| 요금제 | 유료(Pro·Max). 스킬 자체는 무료 요금제에도 있다고 안내한다 | 유료(Plus·Pro). 공식 문서에 스킬의 요금제 조건은 적혀 있지 않다 |
| skill-creator 부르는 법 | 대화에서 "스킬을 만들고 싶다"고 말한다 | Work에서는 `@skill-creator`, Codex에서는 `$skill-creator` |

회사 계정(Team·Enterprise·Business)은 관리자가 스킬 만들기를 꺼 둘 수 있다. 메뉴가 안 보이면 먼저 관리자에게 묻는다.

### 준비물 세 가지

skill-creator는 질문을 많이 한다. 답을 미리 들고 가면 대화가 짧아진다.

1. **1에서 쓴 여섯 칸 초안.** 언제 쓰나, 재료, 순서, 성공 기준, 실패하면 볼 것, 하지 말 것과 승인.
2. **잘된 결과 하나.** 예전에 만족했던 보고 메일, 공지문 같은 것. 이름·금액처럼 민감한 것은 지운다.
3. **시험할 요청 세 개.** 평소에 할 법한 요청 둘, 일부러 어려운 요청 하나. 예: 자료가 빈 경우.

여기서부터는 내 해석이다. 세 번째가 가장 중요하다. skill-creator도 시험할 요청을 만들어 주지만, **내 일에서 실제로 틀리던 경우**는 나만 안다.

## skill-creator가 하는 일

두 회사의 skill-creator 원문(SKILL.md)을 읽어 보면 흐름이 거의 같다.

| 순서 | 하는 일 | Claude 원문에서 | ChatGPT(Codex) 원문에서 |
| --- | --- | --- | --- |
| 1 | 무엇을 하는 스킬인지 파악한다 | 무엇을 하나, 언제 꺼내나, 결과 모양은 무엇인가, 시험을 할 것인가 | 구체적인 사용 예부터 묻는다. 한 번에 너무 많이 묻지 않는다 |
| 2 | 빈 곳을 묻는다 | 예외 상황, 입력과 결과의 모양, 예시 파일, 성공 기준 | 자주 반복될 자료(참고 문서, 양식)가 무엇인지 정한다 |
| 3 | SKILL.md를 쓴다 | 설명에 "언제 쓰나"를 모두 넣는다 | 설명에 "언제 쓰나"를 모두 넣는다. 본문에는 넣지 않는다 |
| 4 | 시험한다 | 현실적인 요청 2~3개를 만들어 돌려 본다 | 형식을 검사하는 확인을 돌린다 |
| 5 | 고친다 | 내 의견을 듣고 고친 뒤 다시 돌린다 | 실제로 써 보고 고친다 |

두 회사가 같은 말을 하는 곳이 있다. **"언제 쓰나"는 본문이 아니라 설명에 쓴다.** AI는 설명만 먼저 읽고, 스킬을 꺼내기로 정한 뒤에야 본문을 읽기 때문이다. 1의 여섯 칸 중 1번 칸이 설명으로 가고, 나머지 다섯 칸이 본문으로 간다.

여기서부터는 내 해석이다. skill-creator는 2주차 2에서 본 그릴 미와 닮았다. 빈 곳을 묻고, 내가 답하고, 그 답으로 글을 쓴다. 다른 점은 끝에 **시험**이 붙는다는 것이다.

## A. Claude 데스크톱 앱에서

### 1단계. 설정을 확인한다

1. 설정의 **Capabilities**에서 **Code execution and file creation**을 켠다. 새 설정 화면에서는 이름이 **Create and edit files**다. 이것이 꺼져 있으면 스킬이 회색으로 보이고 쓸 수 없다.
2. **Customize → Skills**를 연다. 스킬 목록과 켜고 끄는 스위치가 여기 있다. 목록에 skill-creator가 켜져 있는지 본다.

### 2단계. 새 대화에서 말을 건다

새 대화를 열고 만들고 싶은 스킬을 말한다. 준비물을 같이 붙인다.

```text
스킬을 하나 만들고 싶다. skill-creator를 써서 같이 만들어 줘.

하는 일: 내가 붙여 넣은 이번 주 메모로, 팀장님께 보낼 주간 업무 보고 메일 초안을 쓴다.

아래는 내가 미리 써 둔 여섯 칸 초안이다.
--- 초안 시작 ---
언제: 금요일 오후, 또는 "주간 보고"라고 할 때
재료: 내가 붙여 넣은 이번 주 한 일·이슈·다음 주 계획
순서: 세 칸으로 나눈다 → 한 화면, "~했습니다" 체, 제목 형식을 지킨다
성공 기준: 한 화면 분량, 내가 적은 항목이 하나도 빠지지 않음, 내가 적지 않은 숫자 없음
실패하면: 자료가 비어 있으면 "자료 없음"이라고 알리고 추측으로 채우지 않는다
승인: 메일 발송은 내가 한다. 초안까지만.
--- 초안 끝 ---

잘된 보고 메일 예시 하나를 첨부한다.
질문은 한 번에 하나씩 해 줘. 나는 컴퓨터 용어를 잘 모른다.
```

마지막 줄은 일부러 넣는다. Anthropic의 skill-creator 원문에는 사용자의 말을 보고 용어 수준을 맞추라는 지시가 있다. 그래도 내가 먼저 말해 주면 확실하다.

생각 과정을 펼쳐 보면, Claude가 skill-creator 스킬을 읽는 것이 보인다.

### 3단계. 질문에 답한다

Claude가 내 일에 대해 묻는다. Anthropic 안내서에 나오는 질문은 이런 것이다.

- 이 스킬을 쓰는 때의 예를 들어 줄 수 있나요?
- 이런 일에서 좋은 결과는 무엇인가요?

답할 때 지키는 것이 셋 있다.

- **사실로 답한다.** "깔끔하게"보다 "한 화면, 항목마다 한 줄".
- **모르면 모른다고 한다.** 짐작으로 답하면 그 짐작이 스킬에 박힌다.
- **추천 답을 그냥 받지 않는다.** 2주차 2의 그릴 미와 같다. 말투·길이 같은 것은 받아도 되지만, 금액·날짜·이름 같은 사실은 내가 답한다.

### 4단계. 초안을 읽는다

Claude가 SKILL.md를 쓰고 파일로 묶는다. 설명을 위해 만든 예시로 보면 맨 위는 이런 모양이다.

```text
---
name: weekly-report-email
description: 사용자가 붙여 넣은 이번 주 메모로 팀장에게 보낼 주간 업무 보고 메일 초안을
  쓴다. "주간 보고", "이번 주 보고 메일", "금요일 보고"라고 하거나 한 주의 업무 메모를
  붙여 넣고 정리해 달라고 하면 쓴다.
---
```

읽을 때는 1의 여섯 칸과 대조한다.

| 여섯 가지 | SKILL.md에서 찾을 곳 | 확인할 것 |
| --- | --- | --- |
| 언제 쓰나 | 맨 위 `description` | 내가 실제로 쓰는 말이 들어 있나 |
| 재료 | 본문 | 매번 물어볼 것과 고정된 것이 나뉘어 있나 |
| 순서 | 본문 | 내 순서와 같은가 |
| 성공 기준 | 본문 | 확인할 수 있는 문장인가 |
| 실패하면 볼 것 | 본문 | "지어내지 않는다"가 있나 |
| 하지 말 것과 승인 | 본문 | "보내기는 내가 한다"가 있나 |

내가 말하지 않은 규칙이 들어가 있으면 그 줄을 짚어 묻는다. 그럴듯한 규칙이라도 내 일과 다르면 뺀다.

Anthropic 도움말에는 이름은 64자, 설명은 200자까지라고 적혀 있다. 설명이 길면 줄여 달라고 한다.

### 5단계. 시험한다

skill-creator는 시험할 요청 2~3개를 제안하고 "이걸로 해 볼까요, 더 넣을까요?"라고 묻는다. 여기에 준비물 3번, 내가 만든 어려운 요청을 더한다.

Claude는 요청마다 스킬대로 결과를 만들어 대화에 보여 준다. 원문에 따르면 일반 대화에서는 시험을 한 번에 하나씩 돌리고, Cowork에서는 여러 개를 동시에 돌리고 비교 화면(HTML 파일)도 만든다.

나는 결과를 2주차 2에서 배운 대로 **채점하듯** 본다. 성공 기준을 하나씩 대 본다.

| 시험 요청 | 성공 기준 통과? | 고칠 점 |
| --- | --- | --- |
| 평소 요청 1 | | |
| 평소 요청 2 | | |
| 어려운 요청 (자료가 빈 경우) | | |

### 6단계. 고친다

걸린 곳을 구체적으로 말한다. 2주차 2의 "첫 결과를 고치는 법"이 그대로 통한다.

```text
세 번째 시험에서 다음 주 계획이 비어 있었는데, 네가 "거래처 미팅 준비"를 지어 넣었다.
성공 기준에 "자료에 없는 일정은 쓰지 않는다"를 더하고, 세 시험을 다시 돌려 줘.
나머지는 그대로 둬.
```

모든 시험이 통과할 때까지 고치고 다시 돌린다.

### 7단계. 저장하고 켠다

다 되면 Claude가 스킬 파일을 만든다. 그 파일을 저장한다. 화면에 스킬로 저장하는 버튼이 나오면 누르고, 파일만 받았다면 직접 올린다.

1. **Customize → Skills**를 연다.
2. **+** 버튼을 누르고 **+ Create skill**을 고른다.
3. **Upload a skill**을 고르고 파일을 올린다.
4. 목록에 생긴 스킬의 스위치를 켠다.

ZIP으로 올릴 때는 **ZIP 안에 스킬 폴더가 통째로** 들어 있어야 한다. 파일이 ZIP 맨 위에 바로 있으면 올라가지 않는다. 폴더 이름과 스킬 이름도 같아야 한다.

```text
weekly-report-email.zip
└── weekly-report-email/
    └── SKILL.md
```

### 8단계. 새 대화에서 확인한다

새 대화를 열고 평소처럼 요청한다. 스킬 이름을 부르지 않는다. 설명이 제대로 쓰였다면 Claude가 알아서 꺼낸다.

```text
이번 주 보고 메일 써 줘.
- 거래처 A 견적 발송
- 신규 직원 교육 2회
- 월말 정산 준비 (법인카드 한도 증액 승인 필요)
```

생각 과정을 펼쳐서 내 스킬 이름이 보이는지 본다. 안 보이면 두 가지를 한다.

- 이번에는 "주간 보고 스킬을 써서"라고 이름을 불러 본다. 이름을 부르면 되는데 안 부르면 안 된다면, 설명에 내가 쓰는 말이 빠진 것이다.
- skill-creator에게 "이 스킬의 설명을 고쳐 줘. 나는 보통 '이번 주 보고 메일'이라고 말한다"고 한다.

### 고칠 때와 나눌 때

- **고칠 때**: skill-creator에게 "기존 weekly-report-email 스킬을 고쳐 줘"라고 한다. 원문에는 이때 이름을 바꾸지 말라는 지시가 있다. 스킬 파일을 대화 옆에 열어 둔 상태라면, 고칠 부분을 드래그하고 **Edit with Claude**를 눌러 고쳐 달라고 할 수도 있다.
- **나눌 때**: Team·Enterprise 요금제에서는 스킬 옆 **…** 메뉴의 **Share**로 동료에게 나눌 수 있다. Pro·Max에서는 각자 자기 계정에 올린다.
- **끄거나 지울 때**: 스위치를 끄면 Claude가 그 스킬을 쓰지 않는다. 지울 때는 스킬을 열고 스위치를 끈 뒤 **…** → **Delete**를 누른다.

### 녹화로 만들기 (Mac만)

내가 하는 일을 녹화해서 스킬로 만드는 기능도 있다. Anthropic 도움말에 따르면 Mac용 Claude의 Cowork에서만 되고, Windows와 일반 대화에서는 안 된다. Windows를 쓰는 수강생은 대화로 만든다.

## B. ChatGPT 데스크톱 앱에서 (Work·Codex)

ChatGPT 데스크톱 앱에서는 Work와 Codex 모두 스킬을 쓴다. 부르는 기호만 다르다. **Work에서는 `@`, Codex에서는 `$`**를 쓴다.

### 1단계. 스킬 목록을 연다

데스크톱 앱 사이드바의 **Skills**를 연다. 기본으로 들어 있는 스킬 중에 **Skill Creator**("Create or update a skill", System 표시)가 있는지 본다.

### 2단계. skill-creator를 부른다

- Work: ChatGPT를 고르고 Work를 켠 뒤, 입력창에 `@skill-creator`를 쓰고 말을 잇는다.
- Codex: Codex를 고르고, 입력창에 `$skill-creator`를 쓰고 말을 잇는다.

말할 내용은 A의 2단계 요청과 같다. OpenAI 안내서도 같은 것을 말하라고 한다. 목표, 순서, 원하는 결과 모양, 꼭 넣을 것과 피할 것, 그리고 양식이나 예시가 있으면 함께 준다.

```text
@skill-creator
스킬을 하나 만들고 싶다. 내가 붙여 넣은 이번 주 메모로 팀장님께 보낼
주간 업무 보고 메일 초안을 쓰는 스킬이다.
(이하 A의 2단계와 같은 여섯 칸 초안과 예시)
```

### 3단계. 질문에 답한다

OpenAI의 skill-creator는 **구체적인 사용 예**부터 묻는다. "이 스킬이 어떤 요청에 쓰이나요?", "어떤 말을 하면 이 스킬이 켜져야 하나요?" 같은 것이다. 원문에는 한 번에 너무 많이 묻지 말라는 지시가 있다.

지시문만으로 된 스킬로 할지, 정해진 작업을 하는 작은 프로그램(스크립트)을 같이 넣을지도 묻는다. 기본은 지시문만이다. 보고 메일 같은 글쓰기 스킬은 지시문만으로 충분하다.

### 4단계. 초안을 읽는다

SKILL.md를 읽는 법은 A의 4단계와 같다. 여섯 칸과 대조한다.

Codex에서는 SKILL.md 외에 `agents/openai.yaml`이라는 작은 파일이 하나 더 생긴다. 앱 화면에 보일 이름과 짧은 설명이 들어 있다. 내용을 고칠 일은 거의 없다.

skill-creator가 형식 검사를 돌리기도 한다. 이 검사는 **이름과 설명의 형식만** 본다. 내용이 맞는지는 보지 않는다. 내용은 5단계에서 내가 본다.

### 5단계. 시험한다

새 대화를 열고 시험 요청을 넣는다. 스킬 이름을 직접 불러도 되고(`@weekly-report-email`, `$weekly-report-email`), 그냥 요청해서 알아서 꺼내는지 봐도 된다. 둘 다 해 본다.

채점표는 A의 5단계와 같다. 걸린 곳은 A의 6단계처럼 구체적으로 말해 고친다.

```text
@skill-creator
weekly-report-email 스킬을 고쳐 줘. 다음 주 계획이 비어 있을 때 일정을 지어 넣었다.
"자료에 없는 일정은 쓰지 않는다"를 성공 기준에 더해 줘.
```

### 6단계. 어디에 저장되나

- **Codex**: 스킬은 내 컴퓨터의 폴더에 저장된다. 공식 문서에 적힌 사용자 폴더는 `$HOME/.agents/skills`다. Windows라면 `C:\Users\내이름\.agents\skills`일 것이다. 이 Windows 경로는 문서에 직접 적혀 있지 않아서 강의 전에 확인한다. 특정 작업 폴더에서만 쓸 스킬은 그 폴더 안의 `.agents/skills`에 둔다.
- **Work**: OpenAI 안내서는 스킬을 켜 두면 ChatGPT가 맞는 요청에 쓰고, 내가 직접 고를 수도 있다고 한다. 워크스페이스 설정이 허락하면 동료와 나눌 수 있다.

폴더가 바뀌었는데 스킬이 안 보이면 앱을 다시 시작한다.

### 녹화로 만들기 (Mac만)

ChatGPT에도 내가 하는 일을 녹화해 스킬로 만드는 **Record & Replay**가 있다. OpenAI 문서에 따르면 macOS에서만 되고, 컴퓨터 조작(Computer Use) 기능도 켜져 있어야 한다. Work를 켜거나 Codex를 고른 뒤 **Plugins**를 열고, **+** 메뉴의 **Record a skill**을 고른다. 녹화를 마치면 스킬 초안이 만들어진다.

## 두 앱을 나란히 보면

| | Claude 데스크톱 앱 | ChatGPT 데스크톱 앱 |
| --- | --- | --- |
| 시작 | 대화에서 "스킬을 만들고 싶다" | Work `@skill-creator`, Codex `$skill-creator` |
| 묻는 것 | 할 일, 꺼낼 때, 결과 모양, 성공 기준 | 구체적인 사용 예, 꺼낼 때의 말 |
| 시험 | skill-creator가 시험 요청을 만들고 돌려 보인다 | 형식 검사 뒤 내가 새 대화에서 돌린다 |
| 저장 | 스킬 파일을 Customize → Skills에 올린다 | Codex는 `.agents/skills` 폴더, Work는 앱 안 |
| 켜고 끄기 | Customize → Skills의 스위치 | 사이드바 Skills에서 본다 |
| 부르기 | 알아서 꺼낸다. 이름을 말해도 된다 | 알아서 꺼낸다. `@`·`$`로 불러도 된다 |
| 녹화로 만들기 | Mac의 Cowork만 | macOS만 (Record & Replay) |

스킬의 모양은 같다. 두 회사 모두 Agent Skills라는 공개 형식을 따르므로, 한쪽에서 만든 SKILL.md를 다른 쪽에 옮겨 쓸 수 있다. 여기서부터는 내 해석이다. 옮긴 뒤에도 시험 세 개는 다시 돌린다. 같은 글을 읽어도 모델이 다르면 결과가 다를 수 있다.

## 흔한 실수

| 실수 | 왜 문제인가 | 이렇게 한다 |
| --- | --- | --- |
| "보고 메일 스킬 만들어 줘" 한 줄로 시작한다 | skill-creator가 빈칸을 그럴듯하게 채운다 | 여섯 칸 초안과 예시를 같이 준다 |
| 초안을 읽지 않고 저장한다 | 내가 말하지 않은 규칙이 들어갈 수 있다 | 여섯 칸 표로 대조한다 |
| 시험을 skill-creator가 만든 것만 돌린다 | 내 일에서 실제로 틀리던 경우가 빠진다 | 어려운 요청 하나는 내가 넣는다 |
| 스킬 이름을 불러서만 시험한다 | 평소에는 이름을 안 부르므로, 실제로는 안 꺼낼 수 있다 | 이름 없이도 한 번 요청한다 |
| 진짜 고객 정보로 시험한다 | 시험 대화에 민감한 정보가 남는다 | 이름·금액을 바꾼 예시로 시험한다 |

## 실습: skill-creator로 내 스킬 만들기 (20분)

1의 실습에서 쓴 여섯 칸 초안으로 한다.

1. 준비물 세 가지를 모은다. 여섯 칸 초안, 잘된 결과 하나, 시험할 요청 세 개. (5분)
2. 쓰는 앱에서 skill-creator를 부르고 질문에 답한다. (7분)
3. 초안을 여섯 칸 표로 대조하고, 시험 세 개를 돌려 채점한다. (5분)
4. 걸린 곳 하나를 고쳐 달라고 하고, 저장해서 켠다. (3분)

## 강의 전 확인할 것

- [ ] Claude: 설정의 기능 이름(Code execution and file creation / Create and edit files)과 Customize → Skills 위치
- [ ] Claude: skill-creator로 만든 뒤 화면에 저장 버튼이 나오는지, 나온다면 이름이 무엇인지
- [ ] Claude: Windows 데스크톱 앱에서 대화로 만들기가 되는지
- [ ] ChatGPT: 사이드바 Skills와 Skill Creator가 수강생 요금제(Plus)에서 보이는지
- [ ] ChatGPT: Work에서 만든 스킬이 어디에 저장되고 어디서 끄는지
- [ ] Codex: Windows에서 사용자 스킬 폴더의 실제 경로

## 정리

- skill-creator는 묻고, 쓰고, 시험하고, 고친다. 무엇을 넣을지와 합격 여부는 내가 정한다.
- 여섯 칸 초안, 잘된 결과 하나, 시험할 요청 세 개를 들고 시작한다.
- "언제 쓰나"는 설명에 들어간다. 이름을 부르지 않아도 꺼내는지 꼭 시험한다.
- Claude는 Customize → Skills에 올려 켜고, ChatGPT는 Work에서 `@`, Codex에서 `$`로 부른다.
- 두 앱의 스킬은 같은 형식이다. 옮겨도 시험은 다시 한다.
