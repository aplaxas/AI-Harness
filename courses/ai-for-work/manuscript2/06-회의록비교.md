# 6. 같은 업무, 두 에이전트 — 회의록

> [목차](index.md) · 이전: [5. 업무 위임 가이드](05-위임가이드.md) · 다음: [7. 여러 단계의 업무 — 문의·매출 보고](07-다단계비교.md)
>
> 2주차 두 번째 시간이다. 실습자료: [사례 1. 회의 메모 → 회의록](실습자료/README.md)

## 이 시간의 목표

5에서 만든 회의록 설계서 한 장을 Codex·ChatGPT Work와 Claude Cowork에 각각 옮겨 실행하고, 가이드의 각 항목이 두 도구에서 어디에 들어가는지 비교할 수 있다.

## 핵심 한 줄

**설계서는 그대로다. 옮기는 자리만 다르다. 그리고 도구가 비워 둔 자리는 설계서가 메운다.**

## 두 도구를 한 줄로

| | Codex·ChatGPT Work | Claude Cowork |
| --- | --- | --- |
| 무엇인가 | ChatGPT 데스크톱 앱의 작업 모드. 개발용 Codex와 한 앱에 있다 | Claude 데스크톱 앱의 작업 기능. 2026년 9월부터 일반 대화와 합쳐지는 중 |
| 내 폴더를 쓰려면 | 데스크톱 앱(macOS, Windows). 웹·모바일은 클라우드에서만 돈다 | 데스크톱 앱(macOS, Windows). 앱이 열려 있어야 한다 |
| 요금제 | 무료 요금제부터 쓸 수 있다. 쓸 수 있는 양은 요금제마다 다르다 | 유료 요금제(Pro 이상). 무료는 뒤따를 예정 |

두 도구 모두 화면 이름이 자주 바뀐다. 아래 표의 메뉴 이름은 2026년 10월 공식 문서 기준이고, 강의 전에 실제 화면으로 다시 확인한다.

## 준비: 복사본 두 개

[실습자료](실습자료/README.md)의 `사례1-회의록` 폴더를 두 번 복사한다.

```text
내 작업 위치/
├── 사례1-회의록_Codex/
└── 사례1-회의록_Cowork/
```

같은 폴더를 두 도구에 함께 주지 않는다. 한 도구의 결과가 다른 도구의 자료로 섞이기 때문이다.

## 설계서를 두 도구에 옮기기

5의 설계서를 항목별로 옮긴다. 일곱 번째 항목 "기록과 재사용"은 [8](08-지침과내업무.md)에서 따로 비교한다.

### 1. 목표와 완료 기준

| Codex·ChatGPT Work | Claude Cowork |
| --- | --- |
| 데스크톱 앱에는 목표 기능(`/goal`)이 있다. 목표 문장이 첫 요청이자 완료 기준이 된다. 목표가 흐리면 `/plan`으로 시작하면 질문을 통해 성공 기준을 함께 만든다 | 따로 목표 기능은 없다. 요청을 받으면 먼저 계획을 세워 보여 주고, 내가 그 접근을 확인한 뒤 진행시킨다 |

**그대로인 것**: 완료 기준의 내용. "메모 3개마다 회의록 1개, 모든 할 일에 담당·기한 칸"은 어느 도구에 넣어도 같다. Work는 그것을 목표 칸에, Cowork는 요청서 안에 넣을 뿐이다.

### 2. 작업 폴더

| Codex·ChatGPT Work | Claude Cowork |
| --- | --- |
| 입력창 위에서 Chat이 아니라 **Work**를 고르고, 실행 위치를 클라우드가 아닌 **로컬**로 한다. 폴더는 프로젝트에 추가한다(프로젝트 편집 → 폴더 추가). 쓰기는 기본적으로 작업 폴더 안으로 제한된다 | 입력창에서 **Work in a folder**로 내 컴퓨터의 폴더를 고른다. 연결한 폴더 안에서는 읽기·쓰기·지우기가 모두 가능하다. 허락한 폴더 목록은 설정의 **Trusted folders**에서 본다 |

**그대로인 것**: 원본·참고·결과로 나눈 복사본 폴더. Cowork 공식 안내도 전용 작업 폴더를 쓰고 백업해 두라고 권한다.

### 3. 권한과 승인

| Codex·ChatGPT Work | Claude Cowork |
| --- | --- |
| 입력창 아래에서 권한 방식을 고른다. **Ask for approval**(승인 요청, 권장 시작점) / **Approve for me**(자동 검토) / **Full access**(전체 접근). Full access는 작업 폴더 밖까지 손댈 수 있어 데이터를 잃을 수 있다 | 메시지 상자에서 고른다. **Manual**(기본, 행동 전에 묻는다) / **Auto**(안전 검사 후 진행) / **Skip**(검사 없음). 파일을 영구 삭제할 때는 어떤 방식이든 승인을 받는다 |

**그대로인 것**: 처음에는 가장 조심스러운 방식으로 시작한다. 이 실습은 두 도구 모두 **승인 요청 방식**(Work의 Ask for approval, Cowork의 Manual)으로 한다. Full access와 Skip은 쓰지 않는다.

### 4. 위임 요청서

| Codex·ChatGPT Work | Claude Cowork |
| --- | --- |
| Work 모드의 입력창에 쓴다. OpenAI 안내는 결과물, 쓸 자료, 제약, 언제 멈춰 검토·승인받을지를 넣으라고 한다 | 입력창에 쓴다. 공식 안내는 원하는 결과를 설명하고 완성된 작업을 받으라고 한다 |

**그대로인 것**: 요청서 상자 전체. 5의 요청서를 **한 글자도 바꾸지 않고** 두 도구에 붙여 넣는다. 폴더 이름만 각자의 복사본으로 바꾼다.

### 5. 진행 확인

| Codex·ChatGPT Work | Claude Cowork |
| --- | --- |
| 실행 중 옆 패널에 계획, 참고 자료, 만든 파일이 보인다. 목표를 쓴 경우 진행 줄에서 일시정지·재개·수정할 수 있다. 실행 중에 메시지를 보내 방향을 바꿀 수 있다 | 단계마다 진행 표시가 나오고 어떤 방식으로 하는지 보여 준다. 실행 중에 멈추거나 방향을 바꿀 수 있다 |

**그대로인 것**: "계획 먼저, 첫 파일 하나 먼저". 두 도구 모두 요청서의 이 문장대로 멈춘다. 첫 회의록이 나오면 결정·논의 구분부터 보고 나머지를 맡긴다.

### 6. 결과 검수

| Codex·ChatGPT Work | Claude Cowork |
| --- | --- |
| 만든 문서·표·PDF를 채팅 옆에서 미리 본다. 변경 목록과 되돌리기(Review 패널, Revert)는 있지만 **Git 저장소 안의 폴더에서만** 작동한다. 일반 사무 폴더에서는 쓸 수 없다 | 결과물을 미리 보고 내려받는다. 변경 파일 목록, 비교, 되돌리기 기능은 공식 문서에 없다. 백업을 권한다 |

여기가 이 시간의 핵심이다. **두 도구 모두, 일반 사무 폴더에서는 "무엇을 바꿨는지" 한눈에 보여 주는 기능이 없다.** 그래서 설계서가 그 자리를 메운다.

- 2번 **복사본 폴더**: 원본이 바뀌어도 원래 자료는 안전하다.
- 4번 **완료 보고**: 만든 파일 목록을 도구가 직접 말하게 한다.
- 6번 **내 확인**: 원본 폴더를 직접 열어 파일 개수와 수정 날짜가 그대로인지 본다.

여기서부터는 내 해석이다. 도구의 기능은 계속 좋아질 것이다. 언젠가 두 도구 모두 일반 폴더의 변경 목록을 보여 줄 수 있다. 그래도 설계서는 버리지 않는다. 도구가 바뀌어도 내가 확인할 것은 그대로이기 때문이다.

## 시연 순서

강사 화면으로 두 도구를 번갈아 진행한다. 수강생은 따라 한다.

1. 두 앱에서 각자의 복사본 폴더를 연결한다.
2. 권한을 승인 요청 방식으로 맞춘다.
3. 5의 요청서를 그대로 붙여 넣는다.
4. 두 도구가 보여 주는 계획을 나란히 놓고 비교한다.
5. 첫 회의록을 받아 검수표로 본다. 고칠 점이 있으면 같은 문장으로 두 도구에 요청한다.
6. 나머지 두 메모를 맡긴다.
7. 완료 보고를 받고, 원본 폴더를 직접 열어 확인한다.

## 검수표: 두 결과를 같은 기준으로

| 확인할 것 | Codex·ChatGPT Work | Claude Cowork |
| --- | --- | --- |
| 결과 파일 수와 이름이 요청대로인가 | | |
| 원본 폴더의 파일 3개가 그대로인가 | | |
| 결정과 논의가 바르게 나뉘었나 (물음표, "얘기가 나왔다") | | |
| 회의마다 참석자가 메모와 같은가 | | |
| 담당자·기한이 메모에 없을 때 "미정"으로 두었나 | | |
| 요일·날짜를 바꿨다면 달력과 맞는가 | | |
| 메모에 없는 줄이 생기지 않았나 | | |
| 완료 보고에 "내가 확인할 점"이 있었나 | | |
| 시작부터 완료까지 내가 승인한 횟수 | | |

결과가 다르면 어느 쪽이 맞는지는 원본 메모로 판단한다. 다른 도구의 결과로 판단하지 않는다.

> ✍️ **[채우기]** 같은 회의록 업무를 두 도구에 맡겨 본 실제 비교. 계획의 차이, 첫 결과의 차이, 승인 횟수, 검수표에서 갈린 항목을 말한다.

## 실습: 내 업무를 두 도구에 (30분)

1. 5에서 쓴 내 업무 설계서를 꺼낸다.
2. 내 자료의 복사본을 두 개 만든다. 개인정보와 기밀은 지운 상태로.
3. 한 도구를 골라 설계서대로 맡기고, 시간이 남으면 다른 도구에도 맡긴다.
4. 위 검수표를 내 업무에 맞게 고쳐 채운다.

## 정리

- 요청서와 검수 기준은 두 도구에서 똑같다. 다른 것은 폴더 연결, 권한 방식, 진행 표시가 있는 자리다.
- 처음에는 두 도구 모두 승인 요청 방식으로 한다.
- 일반 사무 폴더에서는 두 도구 모두 변경 목록과 되돌리기가 없다. 복사본 폴더, 완료 보고, 내 확인이 그 자리를 메운다.

## 과제

내 업무를 두 도구 중 하나로 끝까지 처리하고, 설계서·결과·검수표·고친 점을 가져온다. 3주차에 다른 도구로 같은 일을 해 보고 비교한다.
