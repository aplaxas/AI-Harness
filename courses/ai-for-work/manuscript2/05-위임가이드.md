# 5. 업무 위임 가이드 — 어떤 에이전트를 써도 같은 설계

> [목차](index.md) · 이전: [4. 회사별 최신 모델](04-최신모델.md) · 다음: [6. 같은 업무, 두 에이전트 — 회의록](06-회의록비교.md)
>
> 2주차 첫 시간이다.

## 이 시간의 목표

채팅과 작업 위임의 차이를 알고, 도구와 상관없이 쓸 수 있는 업무 위임 가이드 일곱 항목으로 업무 하나를 설계할 수 있다.

## 핵심 한 줄

**도구 사용법은 바뀐다. 설계는 그대로다. 설계를 먼저 하고 도구에 옮긴다.**

## 2·3주차의 구조

2·3주차는 도구별 사용법 강의가 아니다.

1. 먼저 **어떤 에이전트를 써도 똑같이 적용되는 가이드**를 세운다. 이번 시간이다.
2. 같은 업무 하나를 **Codex·ChatGPT Work**와 **Claude Cowork**에 나란히 맡긴다.
3. 가이드의 각 항목이 두 도구에서 **어디에, 어떻게** 들어가는지 비교한다.

여기서부터는 내 해석이다. 도구의 메뉴 이름과 화면은 몇 달마다 바뀐다. 2026년 9월에 Claude가 대화와 Cowork를 합친 것처럼, 도구 자체가 합쳐지거나 이름이 바뀌기도 한다. 메뉴를 외운 사람은 화면이 바뀌면 처음부터 다시 배워야 한다. 설계를 아는 사람은 새 화면에서 "폴더는 어디서 고르지? 승인은 어디서 정하지?"만 찾으면 된다.

## 채팅과 작업 위임

| | 채팅 | 작업 위임 |
| --- | --- | --- |
| 자료 | 내가 붙여 넣는다 | 도구가 폴더에서 직접 읽는다 |
| 결과 | 대화창의 글 | 파일, 또는 연결된 서비스의 변경 |
| 결과를 옮기는 일 | 내가 한다 | 도구가 한다 |
| 한 번에 다루는 양 | 붙여 넣은 만큼 | 폴더 안의 여러 파일 |
| 잘못됐을 때 | 쓰지 않으면 끝 | 원본 파일이 이미 바뀌었을 수 있다 |

**에이전트**는 목표를 받으면 계획을 세우고, 파일을 읽고, 결과를 만드는 여러 단계를 스스로 이어서 처리하는 AI 도구다. Codex·ChatGPT Work와 Claude Cowork가 여기에 속한다.

작업 위임은 옮기는 수고를 줄여 준다. 대신 **확인할 범위가 넓어진다.** 채팅에서는 결과를 손으로 옮기는 과정이 그 자체로 한 번의 검토였다. 위임에서는 그 과정이 사라진다. 그래서 설계가 필요하다.

## 업무 위임 가이드: 일곱 항목

| 항목 | 정하는 것 | 이걸 안 정하면 |
| --- | --- | --- |
| 1. 목표와 완료 기준 | 무엇이 되면 끝인가, 결과물은 무엇인가 | 도구가 멈출 곳을 모른다. "다 했습니다"가 정말 다 한 것인지 판단할 수 없다 |
| 2. 작업 폴더 | 원본·작업본·결과를 어떻게 나누나 | 원본이 고쳐지거나 지워진다 |
| 3. 권한과 승인 | 무엇을 읽고 쓰게 하나, 어느 단계에서 내 승인을 받나 | 보내면 안 될 메일이 나가고, 지우면 안 될 파일이 지워진다 |
| 4. 위임 요청서 | 목적·자료·조건·결과 형식, 하지 말 것 | 그럴듯하지만 쓸 수 없는 결과가 나온다 |
| 5. 진행 확인 | 계획과 중간 결과를 어디서 보고, 언제 멈추나 | 잘못된 방향으로 끝까지 간 뒤에야 안다 |
| 6. 결과 검수 | 무엇을 만들고 고쳤나, 원문 대조와 검산 | 틀린 결과가 내 이름으로 나간다 |
| 7. 기록과 재사용 | 잘된 요청과 고친 이유를 지침으로 남긴다 | 다음에 처음부터 다시 설명한다 |

### 1. 목표와 완료 기준

목표는 "회의록 만들어 줘"가 아니라 "결과물이 무엇이고, 무엇이 되면 끝인가"다.

- 결과물: 파일 이름, 형식(Word, Excel, PDF), 개수
- 완료 기준: "메모 3개 모두 회의록으로 바뀌었다", "모든 할 일에 담당자 칸이 있다(없으면 미정)"
- 끝난 뒤 보고: "무엇을 만들었고, 판단이 필요한 곳이 어디인지 목록으로 알려 줘"

진행 보고와 완료는 다르다. 도구가 "작업을 마쳤습니다"라고 해도 완료 기준과 맞춰 본다.

### 2. 작업 폴더

나는 업무마다 폴더를 하나 만들고 셋으로 나눈다.

```text
회의록작업/
├── 원본/      ← 원래 자료의 복사본. 도구는 읽기만 한다
├── 참고/      ← 양식, 예시, 지난번 잘된 결과
└── 결과/      ← 도구가 만든 파일만 여기에
```

- 원래 자료는 **복사해서** 넣는다. 원래 자리의 파일은 건드리지 않는다.
- 개인정보와 기밀은 넣기 전에 지운다(1주차 [3-1. 보안](03-보안-1.md)).
- 내 문서 폴더 전체나 바탕화면을 통째로 주지 않는다.

### 3. 권한과 승인

세 가지를 나눠 정한다.

| 행동 | 기본 |
| --- | --- |
| 읽기 | 작업 폴더 안만 |
| 만들기·고치기 | 결과 폴더 안만 |
| 지우기, 보내기, 결제, 공개 | 항상 내 승인 |

메일·드라이브·일정 같은 서비스를 연결할 때도 같다. 처음에는 읽기만 허용하고, 보내기·지우기는 필요해질 때 따로 연다. 기준은 1주차 [3-1의 원칙](03-보안-1.md#나의-원칙-털린다고-가정한다)이다. 열어 준 곳은 털린다고 가정하고, 털려도 괜찮은 만큼만 연다.

### 4. 위임 요청서

1주차 [2. 프롬프트](02-프롬프트.md)의 네 칸에 위임용 두 칸을 더한다.

| 칸 | 내용 |
| --- | --- |
| 목적 | 이 결과로 무엇을 하려는가, 누가 읽는가 |
| 자료 | 어느 폴더의 어떤 파일을 쓰나. 상태(확정/검토 중)도 적는다 |
| 조건 | 지킬 것. 자료에 없는 내용은 더하지 않는다 등 |
| 결과 형식 | 파일 형식, 이름 규칙, 저장 위치 |
| **하지 말 것** | 원본 고치기, 지우기, 외부로 보내기 |
| **완료 보고** | 무엇을 만들고 고쳤는지, 내가 확인할 점 목록 |

### 5. 진행 확인

- **시작 전에 계획을 보여 달라고 한다.** "바로 시작하지 말고 어떤 순서로 할지 먼저 보여 줘."
- **중간 결과를 하나 먼저 받는다.** 파일 10개를 처리할 일이면 1개를 먼저 만들게 하고 확인한 뒤 나머지를 맡긴다.
- **멈출 조건을 정한다.** 자료가 이상하거나 판단이 필요한 곳을 만나면 추측하지 말고 멈추고 묻게 한다.

### 6. 결과 검수

1. **변경 목록**: 무엇을 새로 만들었고, 무엇을 고쳤고, 지운 것은 없는지 본다. 원본 폴더가 그대로인지 확인한다.
2. **원문 대조**: 결과의 각 줄이 원본 어디에서 왔는지 맞춰 본다. 누락·추가·바뀐 곳을 표시한다.
3. **검산**: 숫자는 원본의 총합, 건수와 맞춰 본다.
4. **사람이 볼 항목**: 이름, 날짜, 금액, 약속은 반드시 내가 본다.

### 7. 기록과 재사용

잘 끝난 업무는 다음을 남긴다.

- 최종 요청서
- 고친 점과 이유
- 새로 알게 된 "하지 말 것"

이 기록을 도구의 **지침**으로 넣어 두면 다음에 같은 일을 다시 설명하지 않는다. 지침은 매번 자동으로 붙는 기본 설명이다. 지침을 두는 자리는 도구마다 다르다. 3주차에 비교한다.

## 설계서 한 장

일곱 항목을 한 장에 채운다. 이 설계서가 2·3주차 내내 쓰는 기본 틀이다. 도구를 바꿔도 이 종이는 그대로다.

| 항목 | 내 업무 |
| --- | --- |
| 업무 이름 | |
| 1. 결과물과 완료 기준 | |
| 2. 작업 폴더(원본/참고/결과) | |
| 3. 읽기·쓰기 범위, 승인받을 행동 | |
| 4. 요청서(목적·자료·조건·결과 형식·하지 말 것·완료 보고) | |
| 5. 계획 확인, 먼저 받을 중간 결과, 멈출 조건 | |
| 6. 검수: 변경 목록, 대조, 검산, 사람이 볼 항목 | |
| 7. 남길 것 | |

## 시연: 회의록 업무를 설계서로

아래는 설명을 위해 만든 예시다. 다음 시간 [6. 회의록 비교](06-회의록비교.md)에서 이 설계서를 두 도구에 그대로 옮긴다.

| 항목 | 회의록 업무 |
| --- | --- |
| 업무 이름 | 주간회의 메모 → 회의록 |
| 1. 결과물과 완료 기준 | 메모 3개마다 회의록 Word 파일 1개. 모든 할 일에 담당·기한 칸이 있다(없으면 "미정") |
| 2. 작업 폴더 | `회의록작업/원본`에 메모 3개, `참고`에 회의록 양식, `결과`는 비워 둔다 |
| 3. 범위와 승인 | 읽기: 회의록작업 폴더. 쓰기: 결과 폴더만. 지우기·외부 전송 금지 |
| 4. 요청서 | 아래 상자 |
| 5. 진행 확인 | 계획 먼저 보기. 첫 메모 1개만 먼저 만들고 확인 뒤 나머지 |
| 6. 검수 | 원본 폴더가 그대로인가. 결정과 논의가 섞이지 않았나. 담당자·기한이 메모와 같은가 |
| 7. 남길 것 | 최종 요청서, 고친 점, 새 "하지 말 것" |

```text
[목적] 회의에 오지 못한 팀원이 결정 사항과 할 일을 바로 알 수 있게 한다.
[자료] 회의록작업/원본 폴더의 메모 3개. 양식은 회의록작업/참고/회의록양식.md.
[조건] 메모에 없는 내용은 더하지 않는다. 물음표가 붙었거나 "얘기가 나왔다"
       수준은 결정이 아니라 논의로 둔다. 담당자·기한이 없으면 "미정".
[결과 형식] 메모마다 양식에 맞춘 Word 파일 1개. 이름은 "회의록_날짜.docx".
           회의록작업/결과 폴더에 저장.
[하지 말 것] 원본 폴더의 파일을 고치거나 지우지 않는다. 폴더 밖 파일은 열지 않는다.
[완료 보고] 만든 파일 목록과, 메모만으로 판단할 수 없어 내가 확인해야 할 점.

바로 시작하지 말고 어떤 순서로 할지 먼저 보여 줘. 첫 메모 하나만 먼저 만들어 줘.
```

> ✍️ **[채우기]** 내가 설계서 없이 맡겼다가 다시 한 실제 경험, 또는 설계서를 쓰고 맡겨서 달라진 점.

## 실습: 내 업무 설계서 (25분)

1주차 과제로 고른 내 업무를 설계서 한 장에 채운다. 짝과 바꿔 읽고, 서로 "이 항목이 비어 있으면 무슨 일이 생길까?"를 하나씩 묻는다.

## 정리

- 채팅에서 위임으로 가면 옮기는 수고가 줄고 확인할 범위가 넓어진다.
- 일곱 항목: 목표·완료 기준, 작업 폴더, 권한·승인, 요청서, 진행 확인, 결과 검수, 기록·재사용.
- 설계서는 도구를 바꿔도 그대로다. 다음 시간에 이 한 장을 두 도구에 옮긴다.
