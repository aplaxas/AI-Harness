# 8. 지침으로 남기기와 내 업무

> [목차](index.md) · 이전: [7. 여러 단계의 업무 — 문의·매출 보고](07-다단계비교.md)
>
> 3주차 두 번째 시간이자 과정의 마지막 시간이다.

## 이 시간의 목표

잘된 위임을 두 도구의 지침·스킬·예약 작업으로 남기는 법을 비교하고, 내 업무 하나를 설계서로 정리해 발표할 수 있다.

## 핵심 한 줄

**잘된 위임은 기록으로 남겨야 다음에도 잘된다. 남기는 자리는 도구마다 다르지만 남길 내용은 같다.**

## 무엇을 남기나

7번 항목 "기록과 재사용"이다. 6과 7을 끝냈으면 이것이 손에 있다.

- **최종 요청서**: 고치고 고친 끝에 잘 통한 요청
- **고친 점과 이유**: 처음 결과에서 무엇이 틀렸고 요청서의 어느 줄을 바꿨나
- **새 "하지 말 것"**: 해 보고 나서야 알게 된 금지 사항. 예: "고객이 말한 요일을 믿지 말고 달력과 맞춰라"

이것을 어디에 두느냐에 따라 세 가지로 나뉜다.

| 남기는 방식 | 뜻 | 언제 |
| --- | --- | --- |
| **지침** | 대화나 작업마다 자동으로 붙는 기본 설명 | 이 폴더·프로젝트의 일에는 늘 지킬 규칙 |
| **스킬** | 지침과 양식·예시를 한 묶음으로 저장해 이름으로 부르는 것 | 같은 종류의 일을 여러 곳에서 반복할 때 |
| **예약 작업** | 정해진 때마다 같은 일을 자동으로 실행 | 매주·매달 같은 자료로 같은 결과를 낼 때 |

## 두 도구에서 남기는 자리

| | Codex·ChatGPT Work | Claude Cowork |
| --- | --- | --- |
| 프로젝트 지침 | 프로젝트 지침이 그 프로젝트의 모든 채팅에 적용된다. 로컬 프로젝트에서는 기본 폴더의 `AGENTS.md` 파일도 지침으로 읽는다 | 프로젝트마다 **Instructions**(지침), 참고 자료, 메모리, 예약 작업을 둔다 |
| 전체 지침 | 설정의 개인 맞춤(Personalization). Work에 어디까지 적용되는지는 공식 문서에 없다 | 설정 → 일반 → **Instructions for Claude** |
| 스킬 | `@skill-creator`로 대화하며 만든다. 내가 한 작업을 녹화해 스킬로 만드는 **Record & Replay**도 있다(일부 지역) | 설정의 Customize → Skills에서 켜고 끈다. 만든 스킬을 ZIP으로 올린다. Word·Excel·PowerPoint·PDF용 기본 스킬이 있다 |
| 플러그인 | **Plugins** 탭에서 설치하고 `@`로 부른다 | Customize → Plugins → Discover에서 추가하고 `/`로 부른다. 유료 요금제 |
| 예약 작업 | 채팅에서 작업을 만들어 달라고 요청한다. 결과는 **Scheduled**에 쌓인다. 새 Gmail·Slack 메시지 같은 사건으로 시작할 수도 있다. **로컬 예약 작업은 컴퓨터와 앱이 켜져 있어야** 돈다 | 대화에서 요청하거나 **Scheduled → New task**로 만든다. 이름, 요청, 승인 방식, 빈도(매시·매일·매주·평일), 작업 폴더를 정한다. **클라우드에서 돌아 컴퓨터가 꺼져 있어도** 실행된다. 단, 로컬 파일이 필요한 작업은 예외. 유료 요금제 |
| 메모리 | 웹 Work는 계정 메모리. 로컬 Codex의 메모리는 기본으로 꺼져 있다 | 프로젝트별 메모리. 다른 프로젝트로 넘어가지 않는다 |

**그대로인 것**: 남길 내용. 지침 칸에 들어가는 글은 두 도구에서 같다. OpenAI 문서는 반드시 지킬 규칙은 메모리가 아니라 지침 파일에 두라고 안내한다. 메모리는 도구가 알아서 고르고, 지침은 내가 정한 그대로 매번 붙기 때문이다.

### 시연: 회의록 지침 남기기

6에서 잘 끝난 회의록 업무를 지침으로 바꾼다. 아래는 설명을 위해 만든 예시다.

```text
이 프로젝트는 마케팅팀 주간회의 메모를 회의록으로 바꾸는 일이다.

- 양식: 참고/회의록양식.md
- 메모에 없는 내용은 더하지 않는다.
- 물음표가 붙었거나 "얘기가 나왔다", "다시 보기로" 수준은 결정이 아니라 논의다.
- 담당자·기한이 없으면 "미정". 이름을 추측해 채우지 않는다.
- 참석자는 회의마다 메모에 적힌 사람만. 지난 회의 참석자를 가져오지 않는다.
- 요일을 날짜로 바꿀 때는 달력과 맞춘다.
- 원본 폴더는 읽기만 한다. 결과는 결과 폴더에 "회의록_날짜" 이름으로.
- 끝나면 만든 파일 목록과 내가 확인할 점을 보고한다.
```

이 지침을 두 도구의 프로젝트 지침에 각각 넣는다. 그다음에는 요청이 한 줄로 줄어든다.

```text
원본 폴더에 이번 주 메모를 넣었다. 회의록으로 바꿔 줘.
```

## 생화학 연구 개발자 사례: 문헌 조사

나는 생화학 연구 개발자의 문헌 조사 업무를 예로 들어 스킬과 플러그인을 설명한다. 아래는 설명을 위해 만든 시연안이다. 실제 사용 경험이나 검색 결과를 기록한 것은 아니다.

**플러그인**은 특정 업무에 필요한 스킬이나 외부 서비스 연결 도구 등을 묶어 추가하는 확장 기능이다. **스킬**은 특정 일을 처리하는 절차와 자료의 묶음이다. 모든 플러그인의 구성이 같지는 않다.

예로 드는 `life-sciences-literature` 플러그인에는 다음 스킬이 있다. 아래 범위는 이 강의 준비 환경에 설치된 스킬 설명을 기준으로 한다. 다른 앱에서도 같은 이름으로 설치할 수 있다고 전제하지 않는다.

| 스킬 | 맡길 일 | 내가 확인할 것 |
| --- | --- | --- |
| `ncbi-entrez-skill` | PubMed에서 논문을 검색하고 서지정보·초록 등을 조회한다 | 검색어·기간이 맞는가. 제목·저자·발행 정보가 출처와 같은가 |
| `biorxiv-skill` | bioRxiv·medRxiv의 날짜 범위나 논문 식별자로 프리프린트 정보와 정식 출판 연결 정보를 조회한다 | 동료 심사 전 공개 원고인 **프리프린트**인가. 정식 출판 정보가 조회됐는가 |
| `ncbi-pmc-skill` | PMC의 논문 식별자로 공개 접근 여부, 이용 허락 조건, 철회 상태와 파일 주소 정보를 조회한다 | 전문을 볼 수 있는가. 이용 조건과 철회 상태가 어떻게 표시됐는가 |

**PubMed**는 생의학 논문의 서지정보와 초록을 찾는 데이터베이스이고, **PMC**는 논문 전문을 제공하는 저장소다. **서지정보**는 제목·저자·발행 연도처럼 논문을 찾는 데 필요한 정보다. **DOI**는 논문 등을 구별하는 식별자다. PMID는 PubMed의, PMCID는 PMC의 논문 식별자다.

여기서부터는 내 해석이다. 플러그인은 문헌 조사에 필요한 기능을 묶고, 스킬은 검색·조회 절차를 제공한다. 어떤 질문을 조사하고 어떤 근거로 판단할지는 내 설계서에 남긴다.

### 시연: 공개 논문 후보 다섯 편 찾기

나는 비공개 연구 자료를 올리지 않고 공개 검색어로 시작한다. 강의 전에 플러그인의 설치·활성화 상태와 각 스킬의 실행 가능 여부를 확인한다. 수강생은 코드나 터미널 명령 대신 자연어로 요청한다.

```text
[목적] 연구회의에서 읽을 논문 후보를 고른다.
[자료] 공개된 PubMed 자료. 검색 주제는 단백질 열안정성 예측이다.
[조건] 2024년 1월 1일~2026년 10월 16일 발행 자료에서 후보를 최대 5편 찾는다.
       먼저 사용할 검색어와 선정 기준을 보여 주고 내 확인을 기다린다.
       life-sciences-literature의 PubMed 검색·조회 스킬을 사용한다.
       초록만 확인한 논문과 전문까지 확인한 논문을 구분한다.
       조회되지 않은 정보는 추측하지 말고 '미확인'으로 둔다.
[결과 형식] 제목, 연도, PMID 또는 DOI, 출처 링크, 선정 이유,
           실제로 확인한 범위(서지정보/초록/전문)를 표로 정리한다.
[하지 말 것] 없는 논문·식별자·출처를 만들지 않는다.
           초록만 읽고 실험의 세부 조건이나 연구 결론을 단정하지 않는다.
[완료 보고] 검색어, 검색일, 후보 수, 추가로 확인할 항목을 알려 준다.
```

나는 후보 한 편의 식별자를 골라 PMC 조회 스킬로 공개 접근 여부와 파일 주소 정보를 확인하게 한다. **파일 주소를 찾은 것과 전문을 읽은 것은 다르다.** 실제로 열어 확인한 범위를 결과에 표시한다. 프리프린트를 다룰 때는 bioRxiv·medRxiv 조회 스킬로 원고 정보와 정식 출판 연결 여부를 따로 확인한다. 조회되지 않았다고 정식 출판이 없다고 단정하지 않는다.

### 같은 위임 가이드를 적용한다

| 가이드 항목 | 문헌 조사에 적용 |
| --- | --- |
| 1. 목표와 완료 기준 | 후보 최대 5편. 식별자·출처·확인 범위가 있다 |
| 2. 작업 폴더 | 파일로 남길 때는 공개 자료 복사본·참고 기준·결과를 나눈다 |
| 3. 권한과 승인 | 공개 자료 조회에 필요한 범위만 허용한다. 외부 발송은 하지 않는다 |
| 4. 위임 요청서 | 주제·기간·선정 기준·표 형식·추측 금지를 적는다 |
| 5. 진행 확인 | 검색어와 선정 기준을 확인한 뒤 검색한다. 후보를 보고 전문 확인 대상을 고른다 |
| 6. 결과 검수 | 식별자와 링크를 열어 대조한다. 프리프린트·철회 표시·확인 범위를 본다 |
| 7. 기록과 재사용 | 검색어, 검색일, 제외 이유, 출처 확인 규칙을 남긴다 |

나는 재사용할 지침을 다음처럼 남긴다.

```text
문헌 조사에서는 검색어와 검색일을 남긴다.
모든 후보에 PMID·PMCID·DOI 중 조회된 식별자와 출처 링크를 붙인다.
서지정보·초록·전문 중 실제로 확인한 범위를 표시한다.
프리프린트와 정식 출판 논문을 구분하고, 조회되지 않은 상태는 미확인으로 둔다.
논문의 내용 요약과 내 업무에 대한 해석을 나눠 쓴다.
```

### 선택 활동: 내 연구 주제로 요청서 바꾸기 (10분)

나는 수강생에게 공개해도 되는 연구 주제 하나로 위 요청서를 바꾸게 한다. 미공개 실험 결과, 특허 출원 전 아이디어, 개인을 알아볼 수 있는 연구 자료는 예시에 넣지 않는다. 자료 판단은 1주차 [7. 보안](../1-week/07-보안-2.md)의 기준을 따른다.

플러그인을 쓸 수 있으면 후보 한 편의 식별자와 초록을 직접 대조한다. 쓸 수 없으면 강사가 미리 조회해 둔 결과와 출처를 받아 같은 검수를 한다. 이 활동은 연구 개발자의 내 업무 적용 사례로 선택한다.

## 예약 작업은 마지막에

여기서부터는 내 해석이다. 예약 작업은 가장 편하지만 가장 나중에 한다. 사람이 보지 않는 동안 돌기 때문이다. 나는 이 순서를 지킨다.

1. 같은 일을 손으로 맡겨 세 번 이상 잘 끝냈다.
2. 그 요청을 지침으로 남겼고, 지침만으로 한 번 더 잘 끝냈다.
3. 그다음에 예약한다. 결과는 매번 내가 확인하고, 발송·삭제·결제는 예약 작업에 넣지 않는다.

Claude 공식 안내도 단순한 작업부터 예약하고 결과물을 매번 검토하라고 권한다.

| 6. 결과 검수 | 미리보기. 변경 목록·되돌리기는 Git 폴더에서만 | 미리보기·내려받기. 변경 목록·되돌리기 없음 | 완료 보고, 원본 폴더 확인, 원문 대조, 검산 |
| 7. 기록과 재사용 | 프로젝트 지침·AGENTS.md, 스킬, Scheduled(로컬은 컴퓨터 켜짐 필요) | 프로젝트 Instructions, 스킬, Scheduled(클라우드 실행) | 최종 요청서, 고친 이유, 새 금지 사항 |

## 내 업무 발표 (각 2분)

1주차에 고른 내 업무를 설계서 한 장으로 정리해 발표한다. 다른 수강생은 "이 항목이 비어 있으면 무슨 일이 생길까?"를 하나씩 묻는다.

| 발표할 것 | 내 답 |
| --- | --- |
| 업무와 결과물 | |
| 멈춤 자리를 어디에 두었나, 왜 | |
| 두 도구 중 무엇이 맞았나, 왜 | |
| 검수에서 잡은 것 하나 | |
| 지침으로 남긴 문장 하나 | |
| 다음에 해 볼 것 (지침 / 스킬 / 예약) | |

도구 선택의 기준으로 생각해 볼 것:

- 회사가 정한 도구나 이미 쓰는 요금제가 있는가
- 이 일은 컴퓨터가 꺼진 동안에도 돌아야 하는가
- 연결해야 할 서비스(메일, 드라이브, 메신저)가 어느 도구에 맞는가
- 두 결과 중 검수표에서 덜 걸린 쪽은 어디인가

> ✍️ **[채우기]** 내가 내 업무에 최종적으로 고른 도구와 그 이유. 지침으로 남긴 문장과, 그 뒤로 요청이 얼마나 짧아졌는지 말한다.

## 과정 정리

3주 동안 한 것을 다시 본다.

| 주차 | 한 것 | 남은 것 |
| --- | --- | --- |
| 1주차 | 도구·모델 이름 정리, 요청 네 칸, 넣기 전 구분과 학습 설정 | 내 계정 점검표, 고쳐 쓴 요청 |
| 2주차 | 업무 위임 가이드, 같은 업무를 두 도구에 | 내 업무 설계서, 검수표 |
| 3주차 | 멈춤 자리가 있는 여러 단계 업무, 지침으로 남기기 | 지침 한 장, 도구 대응표 |

혼자 계속할 때 지킬 것:

- **설계서 먼저, 도구는 나중.** 새 도구가 나와도 설계서의 일곱 칸이 어디에 들어가는지만 찾는다.
- **복사본 폴더와 승인 요청 방식으로 시작한다.** 익숙해져도 원본은 맡기지 않는다.
- **메일·일정을 연결할 때는 읽기부터.** Claude는 커넥터마다 읽기·쓰기 도구별로 "항상 허용 / 승인 필요 / 차단"을 정할 수 있다. ChatGPT는 이런 제어가 주로 관리자 설정에 있다.
- **예약은 마지막에.** 손으로 세 번, 지침으로 한 번 잘 끝난 뒤에.
