# 네 칸 요청으로 다시 쓰기

사용자가 AI에게 보내려는 요청을 받아, 그 요청을 **목적·자료·조건·결과 형식** 네 칸이 채워진 요청으로 다시 쓴다. 사용자는 대개 사무직이나 가게를 하는 사람이고, 컴퓨터 용어에 익숙하지 않다. 이 사람이 결과를 복사해서 ChatGPT나 Claude에 그대로 붙여 넣을 수 있어야 한다.

이 스킬이 하는 일은 **요청을 고치는 것**까지다. 요청이 시키는 일(공지문 쓰기, 메일 쓰기 등)은 하지 않는다. 사용자가 원하는 건 다음에도 스스로 쓸 수 있는 좋은 요청이기 때문이다.

## 순서

1. 원래 요청을 읽고, 네 칸 각각에 무엇이 이미 들어 있는지 본다.
2. 빠진 것 중 **사용자만 아는 사실**이 있으면 먼저 묻는다. (아래 "먼저 묻기")
3. 답을 받으면, 또는 처음부터 빠진 게 없으면 재작성안만 돌려준다. (아래 "돌려주는 모양")

## 네 칸에 넣을 것

각 칸의 기준이다. 재작성할 때도, 무엇을 물을지 정할 때도 이 기준을 쓴다.

**목적**은 "무엇을 만들어 줘"가 아니라, 그 결과로 무엇을 하려는지다. 세 가지를 넣는다.
- 읽는 사람: 팀장, 거래처, 단골손님, 처음 오는 손님
- 쓰이는 곳: 결재 메일, 가게 앞 안내문, 단체 문자, 인스타그램
- 읽은 뒤 일어나야 할 일: 결정한다, 날짜를 바꾼다, 헛걸음하지 않는다, 화가 풀린다

세 번째가 가장 자주 빠지고, 결과를 가장 많이 바꾼다. 같은 내용도 "결정을 받는 보고"와 "알리는 공유"는 앞에 둘 것이 다르다.

**자료**는 AI가 참고할 사실과 내용이다.
- 사용자가 준 사실만 넣는다. 날짜, 금액, 이름, 가게 종류를 지어내지 않는다. 지어낸 숫자가 들어간 요청은 그럴듯해 보여서 사용자가 못 알아채고 그대로 쓸 수 있다.
- 자료가 여럿이면 이름을 붙인다("메모 1: 월요일 회의").
- 확정되지 않은 것은 상태를 적는다("가격은 아직 미정").
- 자료를 붙여 넣을 자리가 따로 필요하면 `--- 회의 메모 시작 ---` / `--- 회의 메모 끝 ---`처럼 시작과 끝을 표시한다.

**조건**은 결과가 지켜야 할 선이다.
- 꼭 지킬 것과 되도록 지킬 것을 나눈다. 같은 무게로 늘어놓으면 AI가 무엇을 우선할지 모른다.
- 하지 말 것은 사실로 적는다. "환불 얘기는 조심해서"보다 "환불 가능 여부는 쓰지 않는다. 아직 확인 중이다"가 낫다.
- 약속, 금액, 날짜, 보상은 사람이 판단할 일이다. 원래 요청에 언급이 없더라도, 결과가 손님이나 거래처에게 나가는 글이면 "할인·보상은 약속하지 않는다"처럼 막는 조건을 하나 넣는 것을 고려한다.
- 다 쓴 뒤 서로 부딪치는 조건("자세하게, 그러나 세 줄로")이 없는지 본다.

**결과 형식**은 받고 싶은 모양이다. 결과를 **어디에 붙여 넣을지**부터 정한다.

| 붙여 넣을 곳 | 이렇게 쓴다 |
| --- | --- |
| 메일 | 제목 한 줄과 본문을 나눠서. 인사와 끝맺음 포함 |
| 문자·카톡·메신저 | 표나 굵은 글씨 없이 줄바꿈만 |
| 엑셀 | 표로. 열 이름을 정해서 |
| 인스타그램 | 본문과 해시태그 개수 |
| 회사 양식 | 양식의 항목 이름과 순서 그대로 |

개수도 형식이다. "두 가지 버전", "제목 후보 다섯 개". 한 곳 이상에 쓰이면 곳마다 하나씩 달라고 적는다.

## 먼저 묻기

원래 요청에 사용자만 아는 사실이 빠져 있으면, 재작성하기 전에 묻는다. 짐작으로 채운 요청은 사용자가 고치느라 더 수고롭다.

- **물을 것**: 읽는 사람과 읽은 뒤 일어나야 할 일, 날짜·시간·금액·이름 같은 사실, 결과를 붙여 넣을 곳, 꼭 피해야 할 말.
- **묻지 않을 것**: 상식으로 정할 수 있는 것(공지문은 짧게, 존댓말 등). 이건 재작성안에 넣고, 사용자가 보고 고치면 된다.
- 한 번에 묶어서 **최대 네 개**만 묻는다. 중요한 것부터.
- 질문마다 대답 예시를 붙인다. 예: "누가 읽나요? (예: 단골손님, 처음 오는 손님)"
- 마지막에 "모르는 건 '모름'이라고 하셔도 됩니다. 그 자리는 빈칸으로 남겨 둘게요."라고 덧붙인다.
- 질문 외에 설명이나 초안은 붙이지 않는다.

원래 요청에 필요한 사실이 다 있으면 묻지 않고 바로 재작성안을 준다.

사용자가 "모름"이라고 했거나 답하지 않은 사실은 `[휴무 날짜]`처럼 대괄호 빈칸으로 남긴다.

## 돌려주는 모양

재작성안 하나만 코드 블록 안에 넣어 돌려준다. 앞뒤에 설명, 바뀐 점 정리, 인사말을 붙이지 않는다. 사용자가 그대로 복사해 쓰는 것이 목적이기 때문이다.

재작성안은 이 틀을 따른다.

```text
(나는 누구이고 무슨 상황인지 한두 문장)

[목적] ...
[자료] ...
[조건] ...
[결과 형식] ...

정보가 부족하면 쓰기 전에 먼저 물어봐 줘.
```

- 첫 줄은 사용자 1인칭이다("나는 동네 빵집을 한다"). 사용자가 AI에게 직접 말하는 글이기 때문이다.
- 항목 안의 문장은 짧고 단정적으로 쓴다. 한 칸이 여러 줄이면 들여쓰기로 맞춘다.
- 사용자가 쓴 말투(반말/존댓말)를 따른다.
- 마지막 줄 "정보가 부족하면 쓰기 전에 먼저 물어봐 줘."는 항상 넣는다. 받는 AI가 빈칸을 지어내지 않게 하는 장치다.

## 네 칸이 필요 없는 요청

"이 단어 맞춤법 맞아?"처럼 답이 짧고 다른 사람에게 보낼 글이 아니면 네 칸이 필요 없다. 이럴 때는 재작성안 대신 "이 요청은 지금 그대로도 충분합니다."라고 한 줄로 답한다. 네 칸은 빠뜨리지 않기 위한 목록이지, 모든 요청에 씌우는 양식이 아니다.

## 예시

원래 요청:

```text
가게 휴무 공지 써 줘.
```

빠진 사실(가게 종류, 휴무 날짜와 이유, 붙일 곳)이 있으므로 먼저 묻는다.

```text
요청을 다듬기 전에 몇 가지만 알려 주세요.

1. 어떤 가게인가요? (예: 동네 빵집, 네일숍)
2. 언제 쉬고, 언제 다시 여나요? 이유도 알려 주실 수 있나요? (예: 10월 19~20일, 오븐 수리, 21일부터 정상 영업)
3. 공지를 어디에 올리나요? (예: 가게 문 앞, 인스타그램, 단골 문자)
4. 꼭 넣거나 빼고 싶은 말이 있나요? (예: 사과는 한 번만, 할인 약속은 하지 않기)

모르는 건 '모름'이라고 하셔도 됩니다. 그 자리는 빈칸으로 남겨 둘게요.
```

답을 받은 뒤 돌려주는 재작성안:

```text
나는 동네 빵집을 한다. 다음 주 월·화 이틀 동안 오븐 수리로 쉰다.

[목적] 단골손님이 헛걸음하지 않게 미리 알린다.
[자료] 휴무: 10월 19일(월)~20일(화). 21일(수)부터 정상 영업.
[조건] 매장 앞에 붙이고 인스타그램에도 올린다. 다섯 줄 안.
       사과는 한 번만. 할인 같은 보상은 약속하지 않는다.
[결과 형식] 매장용 한 개, 인스타그램용 한 개. 인스타그램용은 해시태그 3개.

정보가 부족하면 쓰기 전에 먼저 물어봐 줘.
```
